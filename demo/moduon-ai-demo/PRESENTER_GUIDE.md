# 모두온 AI 시연 가이드 (발표자용)

> **핵심 메시지 한 문장:** "AI는 자료를 읽고, 고르고, 분류하고, 설명하는 **제안**만 합니다. 확정은 사람이, 계산은 고정 공식이 합니다."

- 소요 시간: 약 18분(질문 제외)
- 방식: **전날 리허설에서 녹화한 실제 AI 응답을 재생**합니다(`./run.sh present`). 발표 중에는 Ollama 속도나 오류에 흔들리지 않고, 인터넷도 필요 없습니다.
- 모든 데이터는 가상 샘플입니다. 발표 시작 때 한 번 말해 둡니다.

---

## 1. 전날 준비 (약 10분)

터미널에서 한 줄씩 입력합니다. **명령어 뒤에 `# 설명`을 붙이지 마세요.** Mac 기본 셸(zsh)에서는 설명이 명령어의 인자로 들어가 오류가 납니다.

**① 최신 코드 받기**

```bash
cd ~/M1nfe/demo/moduon-ai-demo
git pull
```

**② Ollama 켜기** — 새 터미널 창(⌘N)을 열어 입력하고, 창은 그대로 둡니다.

```bash
ollama serve
```

**③ 리허설** — 원래 창에서 입력합니다. 실제 AI로 한 번 돌리고 응답을 녹화합니다(PC에 따라 3~6분, AI 호출 17번).

```bash
./run.sh rehearse
```

끝나면 `[정답 대조 요약]`이 나옵니다. **발표에서 말할 숫자는 이 요약입니다.** 메모해 두세요.
마지막 줄에 나오는 `요금 설계 화면(HTML)` 파일도 `open`으로 열어 미리 한 번 눌러 보세요(단말 탭, 셀러/고객 전환).

**④ 점검**

```bash
./run.sh check
```

"발표 준비 완료"가 나오면 끝입니다.

> ⚠️ **리허설 뒤에 `git pull`을 했다면 다시 리허설하세요.** 코드가 바뀌면 발표 화면에 빨간 경고("입력이 녹화 당시와 다릅니다")가 뜹니다. `./run.sh check`가 이 경우를 잡아냅니다.

## 2. 발표 5분 전

1. 방해 금지 모드를 켭니다(알림 차단).
2. 터미널을 전체 화면(⌃⌘F)으로 바꾸고, 글자를 ⌘+로 두세 단계 키웁니다. 표가 깨지면 한 단계 줄입니다.
3. 아래 두 줄을 입력합니다.

```bash
cd ~/M1nfe/demo/moduon-ai-demo
./run.sh check
```

4. "발표 준비 완료"를 확인합니다. 발표는 녹화본 재생이라 **Ollama는 꺼져 있어도 됩니다.**

## 3. 발표 진행

```bash
./run.sh present
```

화면이 한 단락씩 나오고, **Enter를 누를 때마다** 다음으로 넘어갑니다. 화면에 뜨는 표시는 이렇게 설명합니다: 🤖 AI / ⚙️ 코드 / 🙋 사람 / 🗄️ DB / 🧮 계산.
장면 9에 오면 **요금 설계 화면이 브라우저로 자동으로 열립니다.** 브라우저로 넘어가 보여 준 뒤, 터미널로 돌아와 Enter를 누릅니다.

**이야기의 뼈대:** "통신 3사 전산이 엑셀, 카톡, API, CSV로 제각각 들어옵니다 → AI가 그중 사람이 손으로 옮기던 부분(새 양식 엑셀, 카톡 공지)을 읽습니다 → 코드가 검증하고 사람이 확정합니다 → 한 화면에서 요금제별 월 납부액과 리베이트를 봅니다."

## 4. 예상 질문과 답변

| 질문 | 답변 |
|---|---|
| 전산을 알아서 처리해 주나요? | 사람이 손으로 옮기던 부분을 AI가 대신 읽습니다. 처음 보는 엑셀 양식, 카톡·문자 공지, PDF, 메일이 그 대상입니다. API나 승인된 양식은 AI 없이 자동으로 읽습니다. 다만 돈이 걸린 값(리베이트 변경, 이상 값)은 사람이 한 번 확인하고 확정합니다. 사람이 확인하는 건수는 승인된 양식과 이름이 쌓일수록 줄어듭니다. |
| AI가 틀리면요? | 세 겹으로 막습니다. ① 코드가 AI 결과를 원문과 대조하고, 틀리면 승인 버튼을 잠급니다. ② 확정은 사람이 합니다. ③ AI 쪽 프로그램은 DB 권한상 확정 데이터에 쓸 수 없고, 요금 설계 화면은 확정 데이터만 읽습니다. |
| 리베이트가 고객에게 보이나요? | 아니요. 셀러 화면에만 보이고, 고객 안내 화면에서는 숨겨집니다. 분양몰에서는 총판·대리점·셀러 단계마다 보이는 금액(차감 후 금액)을 정책으로 정하게 됩니다. |
| 리베이트 정산까지 되나요? | 오늘은 통신사 원천 리베이트를 모아 보여 주는 데까지입니다. 총판·대리점·셀러 사이의 배분 규칙과 정산 공식을 알려 주시면 고정 공식으로 넣습니다. AI는 정산 계산에 관여하지 않습니다. |
| 인터넷·TV, 유심, 렌탈도 되나요? | 같은 구조입니다. 상품군마다 항목(예: 인터넷은 약정·결합·경품)과 규칙(예: 경품 한도)을 사전에 추가합니다. 오늘은 휴대폰과 가전 렌탈, 상조로 보여 드렸습니다. |
| 정확도가 몇 %예요? | 오늘 숫자는 시연용 작은 샘플 기준입니다. 실제 전산 파일로 정답 데이터를 만들어 측정하는 것이 첫 단계(Phase 0)입니다. |
| 비용은요? | 오늘은 무료 로컬 모델이라 0원입니다. Claude Haiku 4.5를 쓰면 토큰 100만 개당 입력 $1, 출력 $5입니다. 초기 규모에서는 월 수천~수만 원 수준으로 추정하고, 실제 데이터로 다시 재겠습니다. 초기에는 API 비용보다 사람 검수 시간이 더 큰 비용입니다. |
| 고객 개인정보가 AI로 넘어가나요? | AI에 보내기 전에 개인정보 패턴을 검사하고, 발견되면 보내지 않습니다. 원칙적으로 상품·가격 데이터만 보냅니다. 로컬 모델을 쓰면 외부로 나가지 않습니다. 해외 API로 보내는 경우는 법률 검토가 필요합니다. |
| 계산에 AI가 끼어들 수는 없나요? | 계산 모듈과 화면 모듈은 AI 코드를 아예 불러오지 않습니다(자동 테스트로 확인). 확정 DB만 읽고, 같은 입력이면 항상 같은 결과를 냅니다. |
| 로컬 모델과 Claude는 뭐가 달라요? | 로컬은 무료이고 데이터가 밖으로 나가지 않지만 정확도가 낮을 수 있습니다. Claude는 더 정확하지만 비용이 듭니다. 같은 시연을 두 모델로 돌려 숫자로 비교할 수 있습니다(`./run.sh compare`). |
| 실제로 만드는 데 얼마나 걸려요? | 사전조사 3~4주 뒤, 첫 전산 1개로 MVP를 만들고 나머지 전산으로 넓힙니다. 분양몰(총판·대리점·셀러, 상품군 5개)까지 가면 범위가 커지므로 일정은 따로 잡겠습니다. |

## 5. 문제가 생기면

| 상황 | 대처 |
|---|---|
| 빨간 경고 "입력이 녹화 당시와 다릅니다" | 리허설 후 코드가 바뀐 경우입니다. 발표 전이면 `./run.sh rehearse`를 실행합니다. 발표 중이면 "녹화 이후 프롬프트를 개선해서 뜨는 안내"라고 설명하고 계속합니다. |
| "AI 호출 실패: … 가 없습니다" | 녹화본이 없는 경우입니다. `./run.sh rehearse`를 실행합니다(Ollama 필요). 시간이 없으면 `./run.sh --mode mock --pause`로 대신하되, **"이건 미리 써 둔 예시 응답"이라고 먼저 말합니다.** |
| 리허설이 `Traceback`으로 멈춤 | 코드 오류입니다. 마지막 20줄을 복사해 보내 주세요. 고친 뒤 `git pull` → `./run.sh rehearse`를 다시 합니다. |
| 표가 깨져 보임 | 글자를 한 단계 줄이거나(⌘-) `./run.sh present --width 110`으로 실행합니다. |
